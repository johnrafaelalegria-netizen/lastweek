1)Browser sends HTTP POST /api/setpoint to Flask. 
2) Flask publishes sp:70 over MQTT to the broker. 
3) The broker delivers it on bench/s01/cmd to the node, which moves the light toward 70. 
4) The node publishes the new light level on bench/s01/light. 
5) The broker delivers it to on_message in app.py, which writes the dict latest. 
6) The browser's next GET /api/light reads the dict and the page redraws.
W2 Why does the dict "latest" exist? One sentence:
MQTT messages arrive when the node decides (every 1 s) but HTTP requests arrive when the browser decides (every 2 s) and must be answered at once, so latest stores the newest reading for the route to read without waiting.
W3 How old can the number on the page be, in seconds, and why:
At most 3 seconds: the node publishes every 1 s, so the value in the dict is at most 1 s old when read, and the page polls every 2 s, so 1 + 2 = 3 s.
